LATRA REQUIREMENTS.

- Provide a mechanism/interface where LATRA can directly interrogate and manage on real-time tracking device and update some parameters such as speed limit at any time.
- Ensure that GPS data transmitted to LATRA VTS platform is complete, correct and accurate.
- Ensure compliance with standards specifications of fixed tracking devices as set by LATRA including integration to the system using API provided by LATRA under annexuere-1.
- Provided access and information to LATRA at any given time for the GPS data receiving, integration/middleware platform for auditing and quality assurance purpose
- Provide GPS positioning, alert information, low battery alerts, alerts on Lost connection with tracking units, damage alert from tracking units.
- Updating of GPS values for at least every 3 minutes. During an emergency event especially over-speeding update real-time devices GPS information value with the emergency event ID every second until that event ends/drops.
- Storing of alerts information while disconnected from GSM network and updating back to central server upon connection to GSM network.
- Submit of complete documentation of tracking devices (including all associated protocols) applicable for non BSMART devices.

SPECIFIC EVENTS/ATTRIBUTES TO BE SENT TO THE VTS PLATFORM.

- Vehicle registration number
- Driver's name (Driver identification such as use of i-Button or similar)
- Latitude and Longitude (in decimal degrees)
- Altitude (in meters above sea level)
- GPS timestamp (YYYY-MM-DD HH:MM:SS)
- Speed (km/hr)
- Bearing (Direction in degrees)
- Odometer (km)
- Satellite count (receivable number of satellites)
- HDOP (Horizontal Dilution of Precision-Quality of Signal)
- RSSI (Received Signal Signal Strength Indication)
- LAC (Local Area Code)
- Cell ID
- MCC (mobile country code)
- IMEI (International Mobile Equipment Identity)
- Data Received Time (Time received by Server - (YYYY-MM-DD HH:MM:SS))
- Data Processing Time (Time insert into Database - (YYYY-MM-DD HH:MM:SS))
